# Logic bridge result catalog

## User story
As a Logic musician, I want to discover ready results for my paired session, so that I can explicitly select and fetch a take without copying its UUID.

## Collection contract
- Given a valid session and an authorized control or same-session native, executor, or MCP credential, when `GET /v1/results?sessionId=...` is requested, then the service SHALL apply the existing session scope policy and return `{sessionId, results, nextBeforeResultId}`. Unauthenticated access SHALL follow the existing authentication policy; foreign sessions SHALL be forbidden.
- Given persisted results in a session, when a page is requested, then only results joined to a same-session ready job whose `resultId` matches SHALL appear, in reverse persisted insertion order. Each summary SHALL contain only `resultId`, `jobId`, `instrument`, `frameCount`, `placementSeconds`, and `publicationOrder`. The instrument display label SHALL be truncated to 128 Unicode code points; the stored job instrument remains unchanged. Prompts, credentials, paths, backend task IDs, asset metadata, and audio bytes MUST NOT appear.
- Given a result, when calculating `publicationOrder`, then it SHALL be its one-based position in the session-filtered persisted results array before ready filtering. Unavailable results retain their positions. Other sessions do not affect the number, and restart preserves it without migration. The append-only array MUST NOT be compacted or reordered under this contract.
- Given no limit, when a page is requested, then the limit SHALL default to 50. An explicit limit MUST be an integer from 1 through 100 inclusive; invalid values SHALL return HTTP 400.
- Given a ready result ID in the same session as `beforeResultId`, when a page is requested, then it SHALL contain only older ready results. `nextBeforeResultId` SHALL identify the last returned result if older ready results remain, otherwise null. New appends MUST NOT shift traversal. Missing, foreign-session, or non-ready cursors SHALL receive the same HTTP 400 response.
- Given a valid session with no ready results, when its latest page is requested, then the service SHALL return an empty results array and null cursor. A missing session parameter or inaccessible session SHALL follow the existing scope and validation policy. The existing result detail and asset endpoints SHALL remain unchanged.

## Native lifecycle and notification
- Given a visible paired editor, when a metadata request completes, then the next latest-page poll SHALL be scheduled after five seconds; failures SHALL back off at 5, 10, 20, then 30 seconds maximum. Only one request SHALL be in flight and at most one refresh coalesced. A separate low-priority worker SHALL avoid the user-command slot; the audio callback and GUI timer MUST NOT perform network or file work. Metadata responses SHALL be capped at 256 KiB, with a cancellable five-second overall deadline and a three-second connection timeout.
- Given a request, when credentials, session, or processor state changes, then the worker SHALL use a synchronized immutable snapshot and reject stale replies. A distinct page/navigation epoch SHALL prevent a latest-page reply from replacing an older page currently browsed, while latest-page notification processing remains separate. The GUI MUST NOT wait for network cancellation.
- Given the first successful latest page, when it arrives, then its maximum ready `publicationOrder` (zero for empty) SHALL establish a silent baseline. Later latest pages with a ready order strictly greater than the high-water mark SHALL show a persistent generic `New results available` banner. The mark SHALL advance to the maximum of its prior value and observed ready orders; empty pages and older pages MUST NOT decrease it. An older unseen ID below the mark MUST NOT notify, and pagination MUST NOT notify or update the mark. The notice MUST NOT claim a complete unseen count.
- Given a reconnect or editor reopen in the same session during the processor lifetime, when polling resumes, then the baseline SHALL remain. A different pairing or host state restore SHALL reset it. A manual storage reset requires re-pairing and a new baseline; a future deletion or compaction feature MUST replace this ordering contract before shipping.
- Given a refresh failure, when the catalog is shown, then stale rows and cached audio SHALL remain available with a stale label. Refresh and polling MUST NOT automatically select, fetch, or replace audio. Explicit selection and Fetch SHALL reuse existing audio verification and export behavior. Older pages SHALL remain visible during latest polling; Refresh, Older, Latest, and an Advanced manual UUID fallback SHALL remain available. Empty, loading, and unpaired states SHALL be identifiable.

- Given a result row, when rendered, then it SHALL show instrument, duration as `frameCount / 48000`, signed placement start, and a short UUID with the full value accessible. Pairing and capture controls SHALL precede the scrollable list. Controls SHALL be keyboard accessible, text SHALL meet WCAG AA contrast, and the layout SHALL remain usable at 440×360 and 880×720. No OS notification, sound, or automatic Logic placement SHALL occur.
